# Roadmap

Status: authoritative for milestone intent; details still require implementation plans.

Related docs: `PRODUCT.md` for scope, `ARCHITECTURE.md` for boundaries, `DATA_MODEL.md` for proposed schema.

## V0: technical foundation

Build only:

- secure Electron shell;
- renderer/main/preload separation;
- local storage foundation;
- Pi runtime status;
- verified development/test/type-check commands.

Do not build full study workflows in V0 unless explicitly requested.

## V0.1: first learning loop

Target capabilities:

- sources and source segments;
- concepts and versioning;
- relationships with proposition labels;
- immutable learning events;
- attempts and attempt conditions;
- review units;
- graph snapshots;
- source viewer;
- React Flow concept map;
- labelled edge creation;
- Pi coaching panel;
- reconstruction mode;
- teach-back mode;
- basic review queue;
- deterministic interval scheduler;
- source visibility, hint level and cold-vs-assisted classification.

Initial Pi skills:

- `map-critic`;
- `hint-controller`;
- `teachback-assessor`;
- `challenge-generator`.

## V1.0: adaptive and validated learning

Possible additions after V0.1 evidence:

- FSRS baseline and/or custom half-life scheduler;
- explicit difficulty adaptation;
- misconception recurrence lifecycle;
- challenge verifier pass;
- course-specific assessment calibration;
- graph intelligence and weak-link detection;
- longitudinal reconstruction comparisons;
- deterministic interleaving engine;
- scheduler evaluation metrics;
- Pi RPC/container isolation if needed.

## Do not start here

- Smart AI scheduler before reliable event instrumentation.
- Reinforcement-learning policy.
- Full autonomous tutor agent.
- Large architecture additions before learning UX is proven.

## Preferred build order

```text
Reliable learning-event instrumentation
  → learner-generated concept/relationship graph
  → cold reconstruction
  → evidence-grounded Pi assessment
  → progressive assistance
  → delayed retrieval + transfer measurements
  → enough clean behavioral data
  → learned scheduler
  → adaptive task-selection policy
```

## Completion criteria for documentation split

- Routine implementation no longer requires loading the archived full research report.
- Each task has an obvious small set of docs to read.
- V0, V0.1, V1 and future ideas are distinguished.
- Agent skills and `AGENTS.md` route Pi to the focused docs.
